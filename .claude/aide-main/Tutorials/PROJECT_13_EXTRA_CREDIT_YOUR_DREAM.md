## 📋 Stage 1: Planning

Create these documents BEFORE writing any code:

### PROJECT_BRIEF.md
- What are you building?
- Who is it for?
- What problem does it solve?
- What makes it unique?

### FEATURES.md
- Core features (MVP)
- Nice-to-have features
- Future features
- Anti-features (what it WON'T do)

### ARCHITECTURE.md
- File structure
- Data flow
- State management approach
- External dependencies

### TIMELINE.md
- Milestones
- Estimated hours per milestone
- Dependencies between tasks
- Deadline (set one!)

---

## 🏗️ Stage 2: Setup

### Repository
- Initialize Git
- Create GitHub repository
- Set up branch protection (main)
- Add .gitignore

### Structure
- Create all folders
- Create empty files with purpose comments
- Set up any build tools needed

### Documentation
- README.md skeleton
- CONTEXT.md for AI sessions
- TASKS.md for tracking
- SCOPE.md for boundaries

---

## 💻 Stage 3: Development

### Branch Strategy
```
main (protected)
  └── develop
        ├── feature/user-auth
        ├── feature/data-display
        ├── feature/export
        └── bugfix/login-error
```

### Commit Discipline
- Commit after each working piece
- Meaningful commit messages
- Never commit broken code to main

### Code Quality
- Comments on complex logic
- Consistent naming conventions
- No dead code
- DRY principles

---

## 🧪 Stage 4: Testing

### Test Plan
- List every feature
- Define expected behavior
- List edge cases
- Define pass/fail criteria

### Bug Tracking
- Use GitHub Issues
- Label: bug, enhancement, question
- Priority: critical, high, medium, low
- Link to commits that fix them

---

## 📦 Stage 5: Build

### Optimization
- Minify CSS/JS for production
- Optimize images
- Remove console.logs
- Remove development code

### Verification
- Test the built version
- Check all features work
- Verify on multiple browsers
- Check mobile if applicable

---

## 🚀 Stage 6: Deployment

### Hosting
- GitHub Pages, Netlify, Vercel, or similar
- Custom domain (optional)
- HTTPS enabled

### CI/CD
- Automatic deployment on push to main
- Build verification before deploy
- Rollback capability

### Go Live
- Deploy to production
- Verify live site works
- Share the URL!

---
